1. What Active Directory Is · foundation

📑
2021: the attackers wrote down the playbook

When the Conti ransomware group's internal documents leaked in 2021, they included a step-by-step manual for their own affiliates. It reads like a pentest course: get a foothold, find the Domain Controller, hunt for domain and enterprise admin accounts, enumerate Active Directory, escalate, move sideways, then encrypt everything. That's not a coincidence. Ransomware crews make their money by going from one phished laptop to Domain Admin, because once you own Active Directory, you own every machine it manages.

The exact steps in that leaked playbook are the exact steps in these three labs. You're learning the attack that actually ends most companies' worst days.

Active Directory is the central directory for a Windows network: every user, every computer, every group, every permission, all managed from one or more servers called Domain Controllers. Log into any machine in the domain and the DC decides who you are and what you can touch. That central control is convenient for admins, and it's exactly what makes it a graph an attacker can walk.

🤔 You compromise one ordinary employee's laptop on a 5,000-machine domain. Why is that often most of the way to owning all 5,000, not just the one? Guess.
Answer

Because one domain account can query the entire directory. From that one laptop you can list every user, every group, and who has power over what, then find a chain of permissions that leads from your nobody account to Domain Admin. AD is a graph of who-can-control-whom, and any member can read the map. The attack is finding the shortest path.

2. The Pieces You Need to Know · foundation

A handful of terms carry the whole topic. Learn these six and the attacks in Labs 11 and 12 make sense.

Domain Controller (DC) The server running AD. It authenticates everyone and holds the whole directory. The crown jewel.
Domain The managed group of users and computers, e.g. corp.local. One login works across all of it.
Users & Groups Accounts and the groups they belong to. Domain Admins is the group that owns everything.
OU (Organizational Unit) A folder for organizing users/computers, so policy can be applied to a slice of the domain.
GPO (Group Policy) Settings pushed to machines from the DC. Control a GPO and you control the machines it applies to.
Kerberos How AD proves who you are, using tickets instead of sending passwords. Labs 11–12 abuse exactly this.
🕸️
Why "graph" is the right word

Think of every user, group, and computer as a dot, and every "can control" relationship as an arrow: a user is a member of a group, a group has admin rights on a computer, an account can reset the password of another. Your foothold is one dot. Domain Admin is another. The attack is finding a path of arrows between them, which is exactly what the BloodHound tool draws for you in §5.

🟢 Baseline · scan a DC, then enumerate users

  1. Scan it. A Domain Controller has a signature set of open ports, learn to recognize it on sight: 
    53   DNS          88   Kerberos      # 88 is the dead giveaway: this is a DC
135  RPC          139/445 SMB
389  LDAP         3268 Global Catalog
  2. Get the domain name from the scan (nmap's output and enum4linux both show it).
  3. Ask the DC for valid usernames with Kerberos, no password needed: 
    kerbrute userenum -d <DOMAIN> --dc <DC_IP> userlist.txt
kerbrute userenum · example output format
[+] VALID USERNAME:  svc-admin@<domain>
[+] VALID USERNAME:  backup@<domain>
[+] VALID USERNAME:  <more users…>

# kerbrute asks the DC "does this user exist?" via Kerberos and the DC
# answers differently for real vs fake names, no login, no lockouts.
# your room's real user list is what you harvest here. write them down.
🔑
Why this works with no password

Kerberos leaks whether a username is valid before you've authenticated: the DC responds one way for a real user and another for a fake one. So you get a clean list of accounts to attack, without a single failed login showing up. Those usernames are the ammunition for Lab 11.

4. Enumerate Again, This Time With a Login · enumerate

The moment you get even one low-privilege account (you'll crack one in Lab 11), the domain opens up. An authenticated user can read almost the entire directory. Same enumeration, far more returned.

🟡 Stretch · what one account gets you

List SMB shares with creds smbclient -L //<DC_IP>/ -U '<user>%<pass>'
Query the directory over LDAP ldapsearch -x -H ldap://<DC_IP> -b "dc=<domain>,dc=<tld>"
What you're hunting Readable shares (backups, scripts with passwords), group memberships, and accounts with too much power.

A single backup or service share with a credentials file in it has ended more domains than any zero-day. Always read the shares.

5. Going Pro: Read the Graph with BloodHound · enumerate

You could trace permission chains by hand. Nobody does. BloodHound collects the whole directory and draws it as a graph, then finds the shortest path from your account to Domain Admin for you. Learning to read that graph is the single most valuable AD skill.

🔴 Going Pro · collect, then trace the path

  1. Run the collector with a domain account to gather every object and relationship: 
    bloodhound-python -d <domain> -u <user> -p <pass> -c all -ns <DC_IP>
  2. Load the data into BloodHound and run "Shortest Path to Domain Admins."
  3. Read the path it draws. Each arrow is a right you can abuse. Here's the shape you're looking for:

The edge labels (MemberOf, GenericAll, WriteDacl, ForceChangePassword) each name a concrete abuse. The whole skill is reading the chain and knowing which arrow to pull. That's what Labs 11 and 12 teach you to actually do.
