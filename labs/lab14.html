1. The Brief · foundation

🏁
This is exactly how the exam works

The eJPT and OSCP exams hand you machines and an IP range and say "get in, get root, prove it, write it up." No walkthrough, no hints, a clock running. Everything in this course has been building the two things those exams actually test: a methodology you run without thinking, and the stubbornness to keep enumerating when you're stuck. Today is your dress rehearsal.

Your mission: own the box end to end, capture both flags (user.txt and root.txt), and hand in a short report that proves how you did it.

The single most common reason people get stuck in a CTF isn't a missing skill, it's stopping enumeration too early. When you're stuck, you've almost always not looked hard enough at something you already found. Go back and read the output again.

2. Your Methodology, as a Checklist · the spine

Work top to bottom. When you're stuck, you're between two of these steps, so return to the one above and dig deeper. This is the exact loop from Labs 07 through 12, compressed to one card.

1 · Recon (Lab 07) nmap -sC -sV -oN scan.txt <IP>. Read every open port and version.
2 · Enumerate (Lab 07) Web → gobuster for hidden pages. Every service → look up its version.
3 · Foothold (Labs 06/08) An upload, a known exploit, or a weak login. Get a shell as a low-priv user.
4 · Privesc (Lab 09) sudo -l, SUID hunt (find / -perm -4000), cron, GTFOBins. Become root.
5 · Loot (Labs 09/12) Grab both flags. Note anything you'd report: how you got in, how you escalated.
6 · Document (Lab 13) Write the two findings and the attack chain as you go, not after.

4. Hints, Only If You're Stuck · 🔴 open nothing to go pro

Each hint is a nudge toward the right phase, not the answer. The real challenge (🔴) is finishing with all of these closed. If you open one, open the smallest one that unblocks you, then close it and keep going.

Stuck at the start: what's even on this box?

Scan it properly before anything else: nmap -sC -sV -oN scan.txt <IP>. Note the web server. Then enumerate the website for pages that aren't linked from the homepage with gobuster dir. You're looking for somewhere that takes input from you, like an upload or a login.

Found an upload form, but my shell won't upload or run

Think back to Lab 06. The server is filtering by extension. When .php is blocked, the question is: what other extensions does this server still run as PHP? Try the alternatives, and remember to find where the file lands (the uploads directory you found while enumerating) so you can trigger it. Start your listener (nc -lvnp) before you fire the shell.

I have a shell as a low-priv user, now what?

Lab 09, in order. sudo -l first. Then hunt SUID binaries: find / -perm -4000 -type f 2>/dev/null. Read the list carefully, one entry that shouldn't have the SUID bit is your way up. When you spot it, look the binary up on GTFOBins for the exact escalation.

General: I've tried everything and I'm stuck

You haven't, and that's not an insult, it's the most reliable fact in hacking. Re-read your nmap and gobuster output line by line. Check versions you skipped. Read every file you can access in the shell you have. The answer is almost always sitting in output you already have and glanced past. Full walkthroughs exist online, but every hint you take is a skill you didn't build, so exhaust your own enumeration first.

SectionWhat goes in it

RemediationThe prioritized fixes for both findings

Flags prove you got in. The report proves you can do this for a living.
