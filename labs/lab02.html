Lab 02: Passive Reconnaissance & OSINT

Collect actionable technical intelligence without generating alert traffic on target defensive sensors. Harvest subdomains, extract DNS zone topologies, query certificate transparency logs, and leverage Shodan search dorks.

📋 Prerequisites & Setup Checklist

1. The Passive OSINT Mindset

Passive reconnaissance gathers intelligence entirely from public archives, search aggregators, and cached third-party services. Because no packet ever transmits directly between the tester's IP and the target's firewall, passive reconnaissance produces zero entries in the target's intrusion detection systems (IDS).

⚠️
Passive vs Active Boundary

Querying Google, Shodan, or Public Certificate Transparency servers is 100% passive. However, running a direct AXFR zone transfer request against the target's authoritative nameserver transmits packets directly to them and counts as active interaction.

2. DNS Interrogation & Zone Transfer Attempts

DNS servers maintain a blueprint of the enterprise perimeter. Using dig, query specific resource records including Mail Exchange (MX), Text verification records (TXT), and Canonical Names (CNAME):

bash — DNS Resource Record Querying 
# Query Nameservers (NS) and Mail Exchangers (MX)
dig mega-corp.one NS +short
dig mega-corp.one MX +short

Attempt an Asynchronous Full Zone Transfer (AXFR). If misconfigured without IP ACLs, the nameserver will leak its entire internal IP and host catalog:

bash — Attempt AXFR Zone Transfer 
dig axfr @ns1.mega-corp.one mega-corp.one

3. OSINT Automation with theHarvester

theHarvester automates passive domain discovery across dozens of public indexes (Bing, Baidu, DuckDuckGo, Yahoo, CertSpotter). Run an automated collection against the authorized practice domain:

bash — theHarvester Multi-Source Query 
theHarvester -d mega-corp.one -b duckduckgo,bing,certspotter -l 200

4. Internet-Scale Intelligence with Shodan CLI

Shodan continuously scans the entire IPv4 address space, indexing open ports, SSL certificates, and service banners. Initialize your API key and filter for targets running exposed administrative interfaces:

bash — Shodan Query Filters 
# Initialize API Key
shodan init YOUR_API_KEY_HERE

# Search for Apache HTTP servers with exposed server-status
shodan search "org:'Target Corp' product:Apache http.title:'Apache Status'"
Thought Question: Why are Certificate Transparency (CT) logs a goldmine for penetration testers?

Whenever an organization requests an SSL/TLS certificate from a Certificate Authority (like Let's Encrypt or DigiCert), that certificate is appended to public, append-only Certificate Transparency logs. Attackers can monitor crt.sh to instantly discover unlinked staging, QA, and internal admin subdomains (e.g., vpn-beta.corp.com, dev-admin.corp.com) the moment they are provisioned.
