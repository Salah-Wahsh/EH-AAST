1. Vulnerability Assessment vs Penetration Testing

A Vulnerability Assessment (VA) is a comprehensive, broad-scope identification of known security flaws across all network hosts without active exploitation. A Penetration Test goes further: proving exploitability, achieving access, chaining flaws, and determining business impact.

🔍
False Positives vs False Negatives

Automated scanners rely on version banners. If an administrator backports a security patch without updating the daemon version number, the scanner flags a False Positive. Conversely, if a customized daemon hides its banner, the scanner misses it (False Negative).

2. Offline Exploit Research with searchsploit

Kali Linux bundles the complete offline Exploit Database repository. Search for verified public exploits matching service versions identified during scanning:

bash — searchsploit Querying 
# Query for ProFTPD vulnerabilities with remote code execution (RCE)
searchsploit proftpd 1.3.5

# Mirror exploit code directly to current working directory
searchsploit -m 37262.py

3. Calculating CVSS v3.1 Base Score Vectors

The Common Vulnerability Scoring System (CVSS v3.1) quantifies technical severity on a 0.0 to 10.0 scale based on eight fundamental metrics:

Metric Code Possible Values Description
Attack Vector AV N (Network) / A (Adjacent) / L (Local) / P (Physical) Remoteness from target
Attack Complexity AC L (Low) / H (High) Race conditions or bypass hurdles
Privileges Required PR N (None) / L (Low) / H (High) Authentication level needed
User Interaction UI N (None) / R (Required) Requires victim click/action
Scope S U (Unchanged) / C (Changed) Impact breaks sandbox / VM container

Example Vector String for an unauthenticated remote code execution flaw:

CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H → Base Score: 9.8 (CRITICAL)

Thought Question: When does CVSS Scope change from Unchanged (S:U) to Changed (S:C)?

Scope changes (S:C) when a vulnerability in one security authority or software boundary impacts resources managed by a completely different security authority. Classic examples include virtual machine escapes (guest to host), cross-site scripting (malicious script running inside a victim browser origin), or container breakouts.
