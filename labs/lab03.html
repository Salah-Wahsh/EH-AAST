Lab 03: Active Scanning & Nmap

Interrogate active network targets with precision. Analyze low-level TCP handshake states, master stealth SYN scanning vs standard Connect scans, perform banner grabbing, and automate vulnerability checks via the Nmap Scripting Engine (NSE).

1. Transport Layer Scanning: SYN vs Connect Handshakes

Understanding how TCP state machines respond to scanning packets is foundational to penetration testing and network forensics:

  • TCP SYN Scan (-sS / "Half-Open"): Client sends [SYN]. If port is open, server responds with [SYN, ACK]. Client immediately sends [RST] to tear down the connection before it completes. Application layer logs are rarely written.
  • TCP Connect Scan (-sT): Client uses the OS connect() syscall to complete the full 3-way handshake ([SYN] → [SYN, ACK] → [ACK]). Guaranteed to log a connection in the target service daemon.
  • Closed Port Response: A closed TCP port responds to any incoming [SYN] with a [RST, ACK] packet.

Execute a stealth SYN scan against target ports 21, 22, 80, and 445:

bash — TCP SYN Stealth Scan 
sudo nmap -sS -p 21,22,80,445 -v 192.168.56.101

2. Comprehensive Port Discovery & Timing Templates

By default, Nmap scans only the top 1,000 most common ports. Penetration testers must audit all 65,535 TCP ports to uncover administrative backdoors or non-standard daemons (e.g. HTTP on port 8080 or 8443).

bash — Full 65,535 Port Scan with T4 Timing 
sudo nmap -sS -p- -T4 --min-rate 1000 -oA target_allports 192.168.56.101

3. Service Version Fingerprinting & OS Detection

Once open ports are mapped, probe them with specific payloads to extract software versions and operating system kernel heuristics:

bash — Version Banner Grab & OS Heuristics 
sudo nmap -sV --version-intensity 8 -O 192.168.56.101

4. Automated Exploitation Audit via Nmap Scripting Engine (NSE)

NSE scripts written in Lua allow Nmap to detect high-severity vulnerabilities without launching a full vulnerability scanner. Execute the vuln script category against the target:

bash — NSE Vulnerability Audit 
sudo nmap -p 80,445 --script vuln -oN nmap_vuln_report.txt 192.168.56.101
Thought Question: Why does TCP SYN scanning require root privileges while TCP Connect does not?

TCP SYN scans craft raw Ethernet and IP frames directly in user-space, manually setting the SYN flag and discarding the kernel's normal socket state table. Creating raw sockets (SOCK_RAW) is restricted to the superuser (root) to prevent unprivileged processes from spoofing packets. In contrast, -sT utilizes standard unprivileged Berkeley socket API calls (connect()).
