1. Fundamental Security Concepts

Ethical Hacking is the authorized simulation of cyberattacks to discover and remediate security vulnerabilities before malicious threat actors can exploit them.

📋 Vulnerability Assessment

BREADTH-FIRST
  • 🎯 Objective: Comprehensive catalog of all potential flaws.
  • ⚙️ Method: Automated, non-intrusive scanning (Nessus, OpenVAS).
  • 🛡️ Exploitation: None — Weaknesses are flagged, not weaponized.
  • 📊 Output: Prioritized risk matrix and CVE score list.
  • ⚡ System Risk: Zero downtime, safe for live production.

🎯 Penetration Test

DEPTH-FIRST
  • 🎯 Objective: Prove real-world business impact and compromise depth.
  • ⚙️ Method: Active simulation of adversarial tactics & custom payloads.
  • 💥 Exploitation: Active — Weaponizes flaws to establish footholds.
  • 📊 Output: Proof-of-concept shells, compromised data & remediation roadmap.
  • ⚡ System Risk: Controlled risk; requires formal Rules of Engagement.

2. The 5 Core Phases of Penetration Testing

Standardized methodologies (NIST SP 800-115, PTES, OWASP) structure engagements into five sequential stages:

PIPELINE: Penetration Testing Lifecycle NIST SP 800-115 / PTES
PHASE 1–2: DISCOVERY

Map attack surface via OSINT, passive queries, and Nmap port scanning to identify open doors (ports 80, 443, 22).

PHASE 3–4: ATTACK

Correlate running software versions with known CVEs, craft weaponized payloads in Metasploit, and secure shell access.

PHASE 5: REMEDIATION

Erase artifacts and deliver clear CVSS risk ratings with actionable mitigation code to prevent black-hat breach.

3. Transport Protocols & Deep Handshake Analysis

Understanding Layer 4 state machines (TCP vs. UDP) is the single most critical prerequisite for penetration testing. Every port scan, reverse shell, and network evasion technique relies directly on how these two protocols establish or omit state.

The TCP 3-Way Handshake: Sequence & Mechanics

Before transmitting a single byte of application data (HTTP, SSH), TCP synchronizes sequence numbers between Client and Target:

SEQUENCE: TCP Three-Way Handshake (RFC 793) State Synchronization & Reliability

Why Do We Need the Handshake? (State & Integrity)

🔢 Initial Sequence Number (ISN) Sync

Both client and server generate random Initial Sequence Numbers (ISNs). The handshake ensures both sides agree on byte offsets so packets arriving out of order or across multiple routes can be reassembled flawlessly.

🛡️ Bidirectional Consent & Buffer Allocation

Before opening kernel socket buffers, the server verifies that the client's IP actually exists and is actively requesting communication, preventing trivial socket starvation and ensuring delivery receipts.

Why Pentesters Care: Port Scanning via TCP Flags

A port scanner (like Nmap) does not guess: it sends TCP probes and infers port states directly from kernel responses:

Probe Sent Target Kernel Response Deducted State What It Means to an Attacker
[SYN] [SYN-ACK] OPEN Service is listening and accepting incoming sockets. Immediate exploit target!
[SYN] [RST] (Reset) CLOSED Host is alive, but no process is bound to this port. Operating system actively rejects connection.
[SYN] No Response / Timeout (or ICMP Unreachable) FILTERED A firewall or packet filter dropped the SYN packet. Probe never reached the host application.
💡
The SYN Stealth Scan ("Half-Open" Scan)

In a normal TCP connection, completing the 3-way handshake causes the target application (e.g. Apache, Nginx) to create a session and log the client's IP in access.log. Pentesters execute SYN Stealth Scans: Kali sends SYN, receives SYN-ACK (confirming the port is open), and immediately transmits a RST packet instead of the final ACK. The connection is aborted before the application layer ever logs the session!

TCP vs. UDP: The Offensive & Defensive Trade-off

⚡ TCP (Connection-Oriented)

STATEFUL
  • Reliability: Guaranteed in-order delivery; dropped packets are automatically retransmitted.
  • Attacker Advantage: Essential for interactive command shells (reverse shells) where lost bytes corrupt shell execution.
  • Attacker Drawback: Strict 3-way handshake makes IP spoofing impossible for interactive sessions.
  • Audit Footprint: Completed connections are logged in web server and firewall state tables.

🚀 UDP (Connectionless)

STATELESS
  • Reliability: Fire-and-forget; zero handshake, zero verification, zero guarantee of receipt.
  • Attacker Advantage: Trivial IP address spoofing (used in DNS/NTP reflection amplification attacks).
  • Attacker Drawback: Extremely difficult to scan: open ports rarely reply (silent), while closed ports generate rate-limited ICMP errors.
  • Audit Footprint: No session state maintained; harder for firewalls to track bidirectional flows.

Web Protocol Anatomy: GET vs. POST

HTTP GET Read-Only Query
  • Payload Location: Appended to URL as query parameters (?user=admin&id=1).
  • Visibility: Logged in browser history, proxy logs & server access logs.
  • Idempotent: Multiple identical requests produce the exact same server state.
  • Cacheability: Cached by default by browsers and CDN edges.
HTTP POST State Mutation
  • Payload Location: Transmitted privately within the HTTP Request Body.
  • Visibility: Hidden from browser URL bar and standard web server access logs.
  • Non-Idempotent: Submitting twice executes two operations (e.g. 2 credit charges).
  • Cacheability: Never cached by default.

Critical HTTP Headers for Pentesters

REQUEST HEADERS (Client ➔ Server)

Host: Target virtual host domain (Crucial for VHost routing).
User-Agent: Browser fingerprint (Spoofable to bypass filters).
Cookie: Session tokens (Target for session hijacking).
Authorization: Base64 credentials for Basic HTTP Auth.

RESPONSE HEADERS (Server ➔ Client)

Server: Banner Leak! Discloses web server software & version.
Set-Cookie: Assigns sessions; audit for missing HttpOnly & Secure.
X-Powered-By: Discloses backend frameworks (e.g. PHP/5.3, Express).
Location: Redirection destination on 301/302 responses.

HTTP Status Code Reference

200 OK Request Succeeded
302 Found Redirect (New URL)
401 Unauthorized Missing / Invalid Auth
403 Forbidden Access Denied by ACL
404 Not Found Resource Missing
500 Server Error Backend Crash / Flaw

  2. Navigate to https://httpbin.org/headers.

🛡️
DevTools Console Security Check: The HttpOnly Flag

Open the Console tab and execute: document.cookie.

If a session cookie has the HttpOnly attribute set by the server, JavaScript returns an empty string, neutralizing Cross-Site Scripting (XSS) cookie theft!

Request Replay: Browser to Terminal (cURL)

Right-click any request in the DevTools Network log ➔ Copy ➔ Copy as cURL to replay and fuzz parameters directly from Kali:

bash — Replay POST Request 
curl -X POST 'https://httpbin.org/post' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-raw 'username=admin_tester&action=auth'

5. Classroom Hands-On Exercises

Exercise 5.1: Base64 Sniffed Credential Decoding SNIFFED AUTH HEADER

You captured an HTTP Basic Auth header: Authorization: Basic dGVhY2hpbmc6aGFja2luZzEyMw==. Decode it:

bash — Decode Base64 Token 
echo "dGVhY2hpbmc6aGFja2luZzEyMw==" | base64 -d
Core Principle: Is Base64 an encryption algorithm?

No! Base64 is an encoding scheme, not encryption. It provides zero confidentiality. Any attacker intercepting cleartext HTTP can decode credentials in a fraction of a second (teaching:hacking123).

Exercise 5.2: Banner Grabbing via cURL RECONNAISSANCE

Extract HTTP response banners without downloading web page bodies:

bash — Banner Grab 
curl -I http://example.com
Why is Server Banner leakage dangerous?

Disclosing web server versions (e.g. Apache/2.2.14) allows adversaries to query the CVE vulnerability database and execute targeted, off-the-shelf exploits in minutes.
