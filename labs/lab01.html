1. Lab Architecture & IP Addressing Scheme

In professional penetration testing engagements, strict network segregation ensures that exploitation packets, malformed TCP payloads, and automated fuzzing scans never bleed into unauthorized production segments or public gateways.

💡
Host-Only vs Bridged Networking

Bridged networking exposes your vulnerable lab targets directly to your physical local area network (LAN), where compromised daemons could be attacked by external peers or cause campus firewall alerts. Host-Only creates a private software switch managed entirely by the hypervisor kernel.

Verify your Kali network interface assignment. Identify the host-only IP address assigned to eth0 or eth1:

bash — Interface Enumeration 
ip -br addr show

2. Configuring Static IP Addressing & Route Validation

DHCP leases can expire and rotate during multi-hour exercises. Assign a persistent static IP address to your Kali attack rig (192.168.56.100) using systemd-networkd or NetworkManager CLI:

bash — Static Configuration with nmcli 
sudo nmcli con mod "Wired connection 1" ipv4.addresses 192.168.56.100/24
sudo nmcli con mod "Wired connection 1" ipv4.method manual
sudo nmcli con up "Wired connection 1"

Verify network reachability to the target machine (192.168.56.101) using ICMP echo requests:

bash — Echo Probe 
ping -c 3 192.168.56.101

3. Linux Firewall (iptables) Isolation Auditing

Before launching any active scanner, inspect your host packet filtering tables to ensure the kernel is not inadvertently routing traffic between the host-only adapter and your external Wi-Fi card.

bash — Inspect iptables Filtering Rules 
sudo iptables -L -n -v
Thought Question: Why must IP forwarding be disabled on the attack rig?

If net.ipv4.ip_forward is set to 1 and your Kali machine is dual-homed (e.g., connected to both the Internet via NAT/Bridged and to the vulnerable target via Host-Only), any malicious payload or worm on the target machine could theoretically route traffic through your Kali VM and reach your physical home or university LAN.

Command to verify: cat /proc/sys/net/ipv4/ip_forward (must output 0).
