1. Fundamental Security Concepts

Ethical Hacking is the authorized simulation of cyberattacks to discover and remediate security vulnerabilities before malicious threat actors can exploit them.

📋 Vulnerability Assessment

BREADTH-FIRST
  • 🎯 Objective: Comprehensive catalog of all potential flaws.
  • ⚙️ Method: Automated, non-intrusive scanning (Nessus, OpenVAS).
  • 🛡️ Exploitation: None — Weaknesses are flagged, not weaponized.
  • 📊 Output: Prioritized risk matrix and CVE score list.
  • ⚡ System Risk: Zero downtime, safe for live production.

🎯 Penetration Test

DEPTH-FIRST
  • 🎯 Objective: Prove real-world business impact and compromise depth.
  • ⚙️ Method: Active simulation of adversarial tactics & custom payloads.
  • 💥 Exploitation: Active — Weaponizes flaws to establish footholds.
  • 📊 Output: Proof-of-concept shells, compromised data & remediation roadmap.
  • ⚡ System Risk: Controlled risk; requires formal Rules of Engagement.

2. The 5 Core Phases of Penetration Testing

Standardized methodologies (NIST SP 800-115, PTES, OWASP) structure engagements into five sequential stages:

PIPELINE: Penetration Testing Lifecycle NIST SP 800-115 / PTES
PHASE 1–2: DISCOVERY

Map attack surface via OSINT, passive queries, and Nmap port scanning to identify open doors (ports 80, 443, 22).

PHASE 3–4: ATTACK

Correlate running software versions with known CVEs, craft weaponized payloads in Metasploit, and secure shell access.

PHASE 5: REMEDIATION

Erase artifacts and deliver clear CVSS risk ratings with actionable mitigation code to prevent black-hat breach.

3. Transport Protocols & Deep Handshake Analysis

Layer 4 transport protocols (TCP vs. UDP) are not just networking trivia — they are the physics of the internet. Every port scan, reverse shell, and evasion technique you will execute in this course relies directly on how these protocols handle state.

📞 TCP: A CERTIFIED PHONE CALL

You dial, the other person answers, you both say "Hello? Can you hear me? Yes!", and you confirm every sentence. If static garbles a word, you ask them to repeat it.

📢 UDP: A MEGAPHONE IN A STADIUM

You shout a message into a crowded room and walk away. You don't know who heard it, you don't wait for a reply, and you can wear a disguise so nobody knows who shouted.

The TCP 3-Way Handshake: Translated into Human Dialogue

Before transferring a single byte of web data or terminal commands, TCP synchronizes byte counters through three mandatory packets:

SEQUENCE: TCP Three-Way Handshake (RFC 793) State Synchronization & Reliability

Why Do Computers Need This Handshake? (The "Why")

🧩 Preventing Scrambled Data (Sequence Sync)

The internet is unpredictable: packets take different paths through routers and arrive out of order. Without agreeing on starting sequence numbers (ISNs), a reverse shell command like rm -rf /tmp/test could arrive as rm -rf /, destroying the machine! Sequence numbers allow the kernel to reassemble fragments in the exact right order.

🛡️ Proof of Existence (Resource Protection)

Opening a network socket consumes real RAM in the server's kernel. The 3-way handshake prevents trivial exhaustion: the server does not allocate full application buffers until the client proves its IP address actually exists and is able to send the final ACK.

How Ethical Hackers Weaponize the Handshake: Knocking on 3 Doors

When you run a port scan in Nmap, Nmap does not have magical x-ray vision. It simply knocks on ports and listens to how the target's operating system reacts:

🚪 1. THE DOOR OPENS PORT OPEN
Kali sends: [SYN] ➔ Target replies: [SYN-ACK]

The Reaction: The target smiled and said *"Welcome, I'm listening!"*
Offensive Meaning: An active software daemon (Apache, SSH, MySQL) is waiting for clients. This is your primary entry point for exploitation!

🚪 2. THE DOOR SLAMS PORT CLOSED
Kali sends: [SYN] ➔ Target replies: [RST] (Reset)

The Reaction: The kernel slammed the door: *"Nobody lives here, go away!"*
Offensive Meaning: The machine is alive, but no program is bound to this port. Don't waste exploit payloads here.

🚪 3. TOTAL SILENCE PORT FILTERED
Kali sends: [SYN] ➔ Target replies: [No Response / Timeout]

The Reaction: Deafening silence. You wait 3 seconds... nothing.
Offensive Meaning: A firewall or packet filter (iptables, AWS Security Group) intercepted your packet and threw it in the trash.

💡
The Hacker's "Ding-Dong Ditch": The SYN Stealth Scan (Half-Open Scan)

The Problem: When you complete the 3rd step of the handshake (sending the final ACK), the target web server (Apache/Nginx) marks you as a connected visitor and writes: 192.168.56.1 connected at 10:45 AM into /var/log/apache2/access.log. The blue team immediately sees you!

The Hacker's Trick (SYN Stealth): Kali sends SYN. The target answers SYN-ACK. At this exact moment, you have your answer — the port is OPEN! Instead of sending the final ACK, Kali abruptly fires a RST (Reset) packet and tears down the connection! Because the handshake was never completed, the operating system never alerts the web server. You verified the port with zero application-layer log footprint!

TCP vs. UDP: The Pentester's Tactical Dilemma

Every penetration tester chooses between TCP and UDP based on what the operation requires:

⚡ TCP (Connection-Oriented)

STATEFUL
  • Reliability: 100% guaranteed delivery. Dropped packets are automatically re-requested.
  • Why Attackers Must Use It: Essential for Interactive Reverse Shells. If packets dropped while typing rm -rf /tmp/test, you could accidentally wipe the server!
  • The Attacker's Limit: You cannot spoof your IP address. If you fake your IP, the target's SYN-ACK goes to someone else, and your connection dies.
  • Blue Team Detection: Easy to detect in firewall state tables and connection logs.

🚀 UDP (Connectionless)

STATELESS
  • Reliability: Fire-and-forget. Zero handshakes, zero delivery receipts, zero state.
  • Why Attackers Exploit It: Trivial IP Address Spoofing! Because UDP has no handshake, you can put the victim's IP on the packet and trick DNS/NTP servers into blasting amplification traffic at them (DDoS).
  • The Attacker's Pain: Scanning UDP is agonizingly slow. Open ports don't say anything (silent), while closed ports return ICMP errors that operating systems rate-limit to ~1 per second. Full UDP scans can take hours!
  • Blue Team Detection: No session state; hard for stateless firewalls to track bidirectional flows.

Web Protocol Anatomy: GET vs. POST (Postcard vs. Envelope)

HTTP GET The Postcard
  • Mental Model: A Postcard. The message is written on the outside for all postal workers, proxies, browser history, and shoulder surfers to see.
  • Payload Location: Appended to the URL bar as query parameters (?user=admin&pass=123).
  • Security Risk: Passwords, session tokens, or API keys in GET requests get saved in browser history, proxy caches, and web server access logs!
  • Idempotent: Safe to repeat 1,000 times; does not alter database state.
HTTP POST The Sealed Envelope
  • Mental Model: A Sealed Envelope. The message is tucked safely inside the envelope body.
  • Payload Location: Transmitted privately in the HTTP Request Body, hidden from the browser URL bar.
  • Security Reality: Much safer for authentication data. Never logged in default server URL logs.
  • Non-Idempotent: Submitting twice executes the action twice (e.g. charging a credit card or transferring funds twice).

Critical HTTP Headers: The Hacker's Leaks

When auditing web applications, headers disclose the backend architecture and security posture:

REQUEST HEADERS (What Kali Sends)

Host: Tells the server which domain you want (essential for virtual host routing).
User-Agent: Your browser fingerprint (pentesters change this to evade bot blockers).
Cookie: Your session passport (the primary target for session hijacking).
Authorization: Credentials encoded in Base64 for Basic HTTP Auth.

RESPONSE HEADERS (What the Target Leaks)

Server: Banner Leak! Discloses software and exact version (e.g. Apache/2.2.8 ➔ instant CVE exploit search!).
Set-Cookie: Sets session tokens. Look closely for missing HttpOnly (XSS theft risk) or Secure (HTTPS-only) flags!
X-Powered-By: Leaks backend framework (e.g. PHP/5.3.10, Express).
Location: The destination URL when redirected (301/302).

HTTP Status Codes: Reading the Server's Mind

200 OK "Success, here is your data."
302 Found "Not here, look over there!" (Redirect)
401 Unauthorized "Who are you? Show authentication."
403 Forbidden "I know who you are, but access is denied."
404 Not Found "Never heard of this URL."
500 Server Error "You broke my backend code!" (Exploit indicator)

4. Interactive Hands-on: Browser DevTools Guide

Before deploying heavy interception proxies like Burp Suite, pentesters utilize browser Developer Tools (F12) to intercept traffic, cookies, and tokens.

Elements Console Network Application
☑ Disable Cache ☑ Preserve Log
STEP 1: NETWORK INSPECTION
  1. Press F12 ➔ open Network tab.
  2. Navigate to https://httpbin.org/headers.
  3. Click the headers request ➔ inspect Headers.
  4. Locate the Server: gunicorn banner disclosure!
STEP 2: POST PAYLOAD INTERCEPTION
  1. Navigate to https://httpbin.org/forms/post.
  2. Submit sample credentials in the form.
  3. Select the logged /post request ➔ open Payload tab.
  4. Notice data is sent in the HTTP body, invisible in the URL bar.
🛡️
DevTools Console Security Check: The HttpOnly Flag

Open the Console tab and execute: document.cookie.

If a session cookie has the HttpOnly attribute set by the server, JavaScript returns an empty string, neutralizing Cross-Site Scripting (XSS) cookie theft!

Request Replay: Browser to Terminal (cURL)

Right-click any request in the DevTools Network log ➔ Copy ➔ Copy as cURL to replay and fuzz parameters directly from Kali:

bash — Replay POST Request 
curl -X POST 'https://httpbin.org/post' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-raw 'username=admin_tester&action=auth'

5. Classroom Hands-On Exercises

Exercise 5.1: Base64 Sniffed Credential Decoding SNIFFED AUTH HEADER

You captured an HTTP Basic Auth header: Authorization: Basic dGVhY2hpbmc6aGFja2luZzEyMw==. Decode it:

bash — Decode Base64 Token 
echo "dGVhY2hpbmc6aGFja2luZzEyMw==" | base64 -d
Core Principle: Is Base64 an encryption algorithm?

No! Base64 is an encoding scheme, not encryption. It provides zero confidentiality. Any attacker intercepting cleartext HTTP can decode credentials in a fraction of a second (teaching:hacking123).

Exercise 5.2: Banner Grabbing via cURL RECONNAISSANCE

Extract HTTP response banners without downloading web page bodies:

bash — Banner Grab 
curl -I http://example.com
Why is Server Banner leakage dangerous?

Disclosing web server versions (e.g. Apache/2.2.14) allows adversaries to query the CVE vulnerability database and execute targeted, off-the-shelf exploits in minutes.
